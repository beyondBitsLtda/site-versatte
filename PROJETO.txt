1. O QUE É
--------------------------------------------------------------------------------
Site vitrine da Versatte Sports (@versatte_sports). Não tem carrinho nem
pagamento: o objetivo é mostrar as camisas (os posts mais recentes do Instagram
e o catálogo completo, com o preço da Versatte) e levar a pessoa a comprar pelo
Direct ou pelo WhatsApp, com a mensagem já montada.

Premissas:
  - funcionar muito bem no celular e se adaptar a tablet e desktop;
  - promoções e campanhas aparecem só no topo (slider), nunca em seção própria;
  - nenhuma menção a origem das camisas; o foco é o produto e a marca.

O site é estático (HTML + CSS + JavaScript puro, sem framework e sem etapa de
build). Basta publicar a pasta em qualquer hospedagem estática.

   "Desenvolvido por Beyond Bits". O link "Card Game" do menu e o slide do topo

4. COMO ATUALIZAR
--------------------------------------------------------------------------------
4.1 Novidades do Insta (automático pelo feed, ou manual pelo camisas.json)
    MODO AUTOMÁTICO (recomendado): a seção sempre mostra os 4 posts mais
    recentes do perfil. Quem lê o Instagram é o Behold (behold.so), que usa a
    API oficial do Instagram e entrega um "feed JSON"; o GitHub Actions
    (.github/workflows/novidades.yml) lê esse feed a cada 6 horas, baixa as fotos
    para assets/posts/, gera js/posts.js e publica sozinho.
    Configuração (uma vez só):
      1. criar conta grátis em behold.so e conectar o Instagram @versatte_sports
         (precisa ser conta profissional: comercial ou criador de conteúdo);
      2. criar um feed do tipo JSON e copiar o link dele;
      3. no GitHub: Settings > Secrets and variables > Actions > New repository
         secret, nome INSTAGRAM_FEED, valor = link do feed;
      4. aba Actions > Novidades do Insta > Run workflow (para a 1ª vez).
    Limites do Behold grátis: até 6 posts, feed atualizado 1 vez por dia e 1.200
    leituras por mês. Por isso o site NÃO lê o feed a cada visita: só o GitHub
    lê (4 vezes por dia, ~120 leituras no mês). O link do feed fica só no
    segredo do GitHub, não no código, para ninguém gastar essas leituras.
    Para rodar no computador (PowerShell):
      $env:INSTAGRAM_FEED = "link do feed"; node tools/instagram.mjs
    Se o feed falhar, a ferramenta não apaga nada: o site fica com os posts atuais.

    Textos dos cards (camisas.json): se o link de um post estiver no
    camisas.json, o card usa os textos de lá; senão, mostra a data do post e o
    começo da legenda (sem hashtags). Campos de cada post:
      link      link do post no Instagram
      etiqueta  selo pequeno do card (ex.: "Modelo Torcedor", "Lançamento")
      titulo    parte em caixa alta (ex.: "Chelsea")
      cursiva   parte em letra cursiva (ex.: "Black & Gold")
      nome      como a camisa aparece na mensagem do Direct/WhatsApp
                (sem o modelo, que o cliente escolhe na janela de pedido)
      mensagem  opcional: texto próprio para a mensagem

    MODO MANUAL (sem o feed configurado): a seção mostra exatamente os posts
    listados em camisas.json. Para trocar: edite camisas.json e rode
      node tools/instagram.mjs
    (precisa de Node 22+ e Edge ou Chrome). A ferramenta baixa só os posts novos,
    com todas as fotos do carrossel em resolução original, legenda, curtidas e
    data, gera js/posts.js (não edite esse arquivo à mão) e apaga de
    assets/posts/ as fotos dos posts que saíram da lista.
    Para atualizar curtidas e fotos de todos:  node tools/instagram.mjs --tudo

4.1a Catálogo (catalogo.json)
    A ferramenta tools/catalogo.mjs lê todos os álbuns da página de categoria
    de cada liga (campo "ligas"), decide o modelo de cada camisa pelas palavras
    do título e traduz o nome (ex.: "Retro Flamengo 00/01 Home S-XXL" vira
    "Flamengo · 2000/01 · Titular", tamanhos P ao 2XL). Baixa a capa e até
    "fotosPorCamisa" fotos de cada álbum, converte para WebP e gera js/catalogo.js.
      node tools/catalogo.mjs            sincroniza: baixa só as camisas novas
                                         e apaga as que saíram da fonte
      node tools/catalogo.mjs --local    só aplica preços/nomes/ligas/ajustes, sem baixar
      node tools/catalogo.mjs --simular  lista como cada álbum seria classificado
                                         (no fim: os times de cada liga e as
                                         camisas sem time reconhecido)
      node tools/catalogo.mjs --tudo     baixa de novo as fotos de todas
      node tools/catalogo.mjs --minutos=90  para de baixar depois de 90 min e
                                         grava o que já baixou (o resto entra
                                         na próxima vez)
    O GitHub Actions (.github/workflows/catalogo.yml) faz a sincronização toda
    segunda-feira às 6h e publica sozinho (com --minutos=95, para caber no
    limite de 2 horas do GitHub); também dá para rodar na hora pela aba
    Actions > Catálogo > Run workflow.
    Campos do catalogo.json:
      fonte          fica VAZIO de propósito: o repositório é público e os
                     arquivos da raiz são publicados no site, então o link da
                     fonte não pode ficar aqui. Ele fica:
                       - no GitHub: segredo CATALOGO_FONTE (Settings > Secrets
                         and variables > Actions), usado pela sincronização semanal;
                       - no computador: arquivo catalogo.local.json
                         ({ "fonte": "link" }), que está no .gitignore e nunca
                         vai para o GitHub. Num computador novo, crie esse arquivo.
                     O modo --local (preços, nomes, ajustes) não precisa do link.
                     Com "ligas", o link só informa o endereço da loja: as
                     páginas lidas são as categorias de cada liga.
                     DOIS FORNECEDORES (desde 13/11/2026): um link por loja, na
                     ordem. No segredo CATALOGO_FONTE, separados por vírgula
                     ("link do 1º,link do 2º"); no catalogo.local.json,
                     { "fonte": ["link do 1º", "link do 2º"] }. Se o catalogo.json
                     tiver categorias de um fornecedor sem link, a ferramenta
                     para sem mudar nada (para não apagar as camisas dele).
      fotosPorCamisa quantas fotos cada camisa mostra na janela, a primeira é a
                     da capa (hoje 3: com 4, as ~5.400 camisas passariam de
                     1 GB, o limite do GitHub Pages). Se diminuir, a ferramenta
                     apaga as fotos que sobram sem baixar nada
      modelos        id, nome, preço e palavras do título que identificam o
                     modelo; a primeira regra que bater vence (Retrô: retro,
                     rerro (erro de digitação comum na fonte), vintage,
                     reissue; Jogador: player); o modelo sem palavras
                     (Torcedor) fica com o resto. PREÇOS: mude aqui e rode
                     node tools/catalogo.mjs --local
      ligas          filtro de ligas do site, nesta ordem. Cada liga tem:
                       id         fixo (não mude: a ferramenta usa para achar
                                  os times de cada liga, na lista CLUBES do
                                  tools/catalogo.mjs)
                       nome       como aparece no site (pode mudar à vontade)
                       categoria  número da página de categoria do 1º
                                  fornecedor de onde vêm as camisas da liga
                                  (um número ou uma lista). "selecoes" não tem
                                  categoria no 1º fornecedor.
                       categoria2 o mesmo, no 2º fornecedor (Seleções: seleções,
                                  Copa 2026 e "Brazil team column"; Outros
                                  times: J-League e outras ligas do mundo).
                                  A Liga Saudita não tem categoria no 2º.
                                  A mesma camisa nos dois fornecedores (mesmo
                                  modelo, time e detalhe) aparece uma vez só, a
                                  do 1º (o --simular lista as repetidas).
                       emblema    imagem do card da liga (assets/ligas/<id>.svg)
                     A liga de cada camisa vem do TIME, não da categoria: a
                     fonte às vezes põe camisas na categoria errada (ex.: um
                     PSV na categoria da Bundesliga). Seleções vão para
                     "Seleções" (inclusive a Seleção Brasileira). Time
                     desconhecido fica na liga da categoria, como "Outros".
                     Camisa de time de uma liga que NÃO está na lista (PSV,
                     Galatasaray, Sporting...) fica de fora do catálogo (ou vai
                     para a liga "outras", se ela existir na lista).
                     Hoje TODAS as ligas que a ferramenta conhece estão na
                     lista ("outras" junta duas categorias da fonte: times de
                     outros países). Para incluir uma liga nova: veja o número
                     da categoria na fonte (o link termina em
                     /categories/<número>), acrescente { id, nome, categoria,
                     emblema }, a lista de times dela em CLUBES no
                     tools/catalogo.mjs, e rode node tools/catalogo.mjs.
                     Emblemas: os de assets/ligas/ vieram da Wikipédia (são
                     marcas das ligas). Recortes feitos para tirar
                     patrocinadores e caber no card: Serie A (enilive), Ligue 1
                     (McDonald's), Liga Portugal (faixa Betclic e moldura),
                     Escócia (só o leão, sem William Hill e SPFL), Liga
                     Argentina (só o escudo LPF, sem o texto) e Liga Chilena
                     (escudo da ANFP sem a faixa Petrobras; é um PNG dentro de
                     um SVG). selecoes.svg e outras.svg são desenhos próprios
                     (globo com estrela; escudo com três pontos).
                     Para reconhecer um time novo, acrescente o nome e o
                     apelido do título na lista da liga em CLUBES (ou SELECOES)
                     no tools/catalogo.mjs. A fonte usa apelidos: M-U
                     (Manchester United), LWP (Liverpool), YW (Juventus),
                     Celtics (Celtic), riverbed (River Plate) etc.
                     Os números das categorias podem ficar aqui (público):
                     sem o link da fonte, eles não identificam a loja.
      excluir       palavras que tiram o álbum do catálogo (feminina, infantil,
                     treino, manga longa, regata, pré-jogo, jaqueta etc.). Para
                     vender um desses tipos, crie um modelo com preço e palavras
                     próprias (ex.: Feminina com "women") e tire a palavra daqui
      esconder       códigos de camisas que não devem aparecer
      ajustes        correções por código, ex.:
                     "200037351": { "time": "Santos", "detalhe": "2025/26 · Neymar Jr" }
                     (aceita time, detalhe, modelo, liga = id da liga e
                     max = maior tamanho; com time e sem liga, a liga vem do
                     time, se ele estiver nas listas da ferramenta)
      destaques      códigos das camisas fixas nos destaques da home, na ordem
                     (até 8), ex.: ["135129801", "259643688"]. Vazio: o site
                     mostra as mais recentes de cada modelo. Depois de mudar,
                     rode node tools/catalogo.mjs --local
    Camisas sem time reconhecido aparecem como "Outros" (veja com --simular).
    Títulos repetidos aparecem uma vez só (mesmo em ligas diferentes: fica o da
    liga que vem antes). Álbuns sem time e sem temporada no título (capas de
    seção, "....") ficam de fora.
    O código da camisa (número do álbum) NÃO aparece na janela da camisa; ele
    vai só na mensagem do pedido, junto com o link
    versattesports.com.br/catalogo#camisa-<código>, que abre a camisa no
    site: é assim que a equipe sabe qual camisa o cliente quer e onde pedir.
    (Links antigos, versattesports.com.br/#camisa-<código> e
    /catalogo.html#camisa-<código>, continuam abrindo.)

4.1c Loja: carrinho e pagamento pelo Mercado Pago (DESLIGADA)
    Está pronta, mas desligada até a conta do Mercado Pago ficar configurada.
    Com "ativa": false no loja.json, NADA da loja aparece: o site nem carrega o
    js/loja.js e o css/loja.css, e pedido.html e politicas.html não estão em
    nenhum link e não aparecem no Google (noindex).
    Para testar antes de liberar: abra o site com ?loja=teste
      (ex.: versattesports.com.br/catalogo?loja=teste). Fica ligado só neste
      navegador, com um aviso "modo de teste" no canto; desliga com ?loja=off.
      Sem "api" no loja.json, o pagamento é simulado no próprio navegador.
    Como funciona: na janela "Quero essa camisa" de uma camisa do catálogo
    aparece "Adicionar ao carrinho" (posts do Instagram continuam só com
    WhatsApp/Direct). O carrinho fica no menu; depois vêm entrega e contato
    (com busca de endereço pelo CEP) e o pagamento na página do Mercado Pago
    (Pix, cartão ou boleto). Na volta, pedido.html mostra aprovado, em análise
    ou não concluído.
    Preço e frete são sempre recalculados pelo servidor (servidor/worker.js),
    com o catálogo e o loja.json publicados no site.
    Cupons de promoção: campo "Cupom de desconto" no carrinho (um por pedido).
    Os cupons ficam só no servidor, na variável CUPONS do Cloudflare (nunca no
    site, que é público): % de desconto, valor em reais ou frete grátis, com
    validade, pedido mínimo, limite de usos e restrição por modelo, time ou
    camisa. Formato e exemplos em servidor/cupons-exemplo.json e passo a passo
    em servidor/LEIA-ME.txt (parte C). Link de promoção: ?cupom=CODIGO em
    qualquer página. No modo de teste sem servidor, o cupom TESTE10 dá 10%.
    Para liberar: siga servidor/LEIA-ME.txt (Cloudflare, Mercado Pago, testes),
    preencha politicas.html, defina frete e prazo no loja.json, coloque o link
    "Políticas da loja" no rodapé das páginas e mude "ativa" para true.

4.1b Formulário "Fale com a gente"
    Seção antes do rodapé (link "Contato" do menu). Nome, e-mail, WhatsApp
    (opcional) e mensagem. O envio é feito pelo FormSubmit (formsubmit.co,
    gratuito, sem cadastro) para o e-mail que está em data-endpoint, no
    <form data-contact> do index.html (hoje: versatte@zohomail.com).

      e-mail de ATIVAÇÃO para esse endereço; é preciso clicar em "Activate".

    - O envio é feito como FormData (não JSON), para o navegador não fazer a

5. COMO FUNCIONA A COMPRA (Direct e WhatsApp)
--------------------------------------------------------------------------------
"Quero essa" abre uma janela onde a pessoa escolhe modelo e tamanho, e o site
monta a mensagem, por exemplo:
  "Olá! Vi no site da Versatte e tenho interesse na camisa Chelsea Black &
   Gold (modelo Torcedor, tamanho G). https://www.instagram.com/p/..."
No catálogo o modelo já vem da camisa (a janela pede só o tamanho, limitado à
faixa da camisa) e a mensagem leva preço, código e link:
  "Olá! Vi no catálogo do site da Versatte e quero a camisa Flamengo 2000/01
   Titular (modelo Retrô, tamanho G, R$ 189,90). Cód. 135129801
   https://versattesports.com.br/catalogo#camisa-135129801"

  - WhatsApp: a mensagem já chega escrita (o link wa.me aceita texto pronto).
  - Direct do Instagram: o Instagram NÃO permite que sites preencham o campo
    do Direct. Por isso o site copia a mensagem no clique e mostra o passo
    "Mensagem copiada! Abra o Direct e cole". O link ig.me também leva o texto
    no parâmetro ?text=, que não é oficial; se um dia o Instagram aceitar, a
    mensagem passa a aparecer sozinha.
  Importante: a cópia precisa acontecer no mesmo instante do clique (é
  síncrona de propósito). Se for adiada, o navegador abre o Direct antes,
  a página perde o foco e a cópia é bloqueada.


6. LIMITES CONHECIDOS
--------------------------------------------------------------------------------
- Comentários dos posts: o Instagram só libera comentários pela API oficial
  (conta comercial + servidor guardando um token de acesso). A prévia mostra
  o número de comentários e leva ao post. Se quiserem exibir comentários no
  futuro, dá para usar um servidor pequeno, como o Cloudflare Worker já usado
  no Versatte Cards.
- A ferramenta tools/instagram.mjs lê a página pública do post como um
  navegador. Se o Instagram mudar o layout dessa página, ela pode precisar de
  ajustes. Vídeos de carrossel não são baixados, só fotos.
- As fotos dos posts trazem a arte original da campanha (inclusive preços da
  época); quando a campanha acabar, vale trocar ou remover esses posts.
- Catálogo: a fonte não deixa usar as fotos dela direto em outro site (bloqueia
  o carregamento fora dela), por isso as fotos são baixadas para
  assets/catalogo/. Se a fonte mudar o layout das páginas, tools/catalogo.mjs
  pode precisar de ajustes. A tradução dos nomes é automática: confira com
  --simular e corrija o que precisar em "ajustes".
- Novidades do Insta no modo automático: o Behold grátis atualiza o feed uma vez
  por dia, então um post novo pode levar até um dia para aparecer no site.
  Curtidas e comentários dependem do que o feed entrega; sem esses números a
  prévia só leva ao post.
- O GitHub Actions publica com o usuário github-actions[bot]. Se um dia o site
  sair do GitHub Pages, rode as ferramentas no computador e publique à mão.


7. IMAGENS E DESEMPENHO
--------------------------------------------------------------------------------
As artes originais (PNG de 2 a 20 MB) foram convertidas para WebP com Python
(Pillow), ficando entre 35 e 240 KB cada, com recortes próprios para celular.
Tamanhos de referência para novas imagens:
  - topo (desktop): ~2000 px de largura; topo (celular): ~900 x 1200 px
  - fotos de detalhe do guia: 1200 x 750 px
As imagens fora da primeira tela carregam só quando a pessoa chega até elas.
Catálogo: tools/catalogo.mjs converte as fotos no próprio Edge/Chrome (canvas),
sem instalar nada: capa de 480 px (cards, ~15 KB) e fotos de 720 px (janela da
camisa, ~20 a 60 KB), ~165 KB por camisa com 3 fotos. O GitHub Pages aceita
sites de até 1 GB: com os dois fornecedores (~5.400 camisas) as fotos ficam
perto de 900 MB. Se passar disso, reduza "fotosPorCamisa" (apaga as fotos que
sobram) ou leve as fotos para um armazenamento à parte.
Arquivos que estão na pasta mas não são usados pelo site:
  assets/*.png (originais), assets/img/retrato-time.webp,
  assets/hero-promoção-02.png e a pasta uploads/.
Se a hospedagem tiver limite de espaço, eles podem ficar fora da publicação.

9. CUIDADOS IMPORTANTES NO CELULAR
--------------------------------------------------------------------------------
- NADA pode passar da largura da tela. No iPhone, um único elemento mais largo
  que a tela faz o navegador encolher o site inteiro (topo e botões ficam
  minúsculos e parece que é preciso arrastar as seções para o lado). Por isso:
    . a textura de fundo (body::before) ocupa exatamente a tela (inset: 0);
    . a faixa de tecido do topo é cortada nas laterais pela própria caixa (.edge);
    . a seção do Versatte Cards corta as laterais (overflow: hidden) e o espaço
      por onde as cartas escapam é padding da própria seção.
  Ao criar algo novo que saia das bordas, mantenha o corte dentro da seção.
- Celular com "Site para computador" (Chrome) ou "Versão para PC" (Samsung
  Internet) ligado: o navegador ignora a tag viewport e desenha a página com
  ~980px, deixando tudo minúsculo. O js/tela.js, carregado no <head> das duas
  páginas logo depois do CSS e sem defer, detecta esse caso (tela de toque
  estreita desenhada larga), amplia a página para o tamanho real e faz as regras
  @media responderem à largura real da tela.
  Por isso, no CSS, use calc(N * var(--vw)) e var(--vh) em vez de vw/vh: o
  script ajusta essas variáveis para compensar o zoom.
- Em celulares baixos (ex.: iPhone SE) o topo usa uma versão compacta para que
  textos e botões caibam na primeira tela.
- O botão flutuante do WhatsApp só aparece depois do topo, para não cobrir os
  botões do hero.
- Os arquivos CSS/JS são chamados com ?v=AAAAMMDD-N no index.html e no
  catalogo.html. Ao publicar mudanças, aumente esse número nas duas páginas para
  o celular não usar uma versão antiga em cache.
- Endereços sem ".html": o GitHub Pages abre /catalogo, /pedido e /politicas
  direto (os arquivos continuam com .html). Por isso os links do site usam "/"
  (home), "/catalogo", "/#guia" etc. Quem abrir um link antigo com .html vê o
  endereço limpo na barra (o js/main.js troca sem recarregar). Testes no
  computador precisam de um servidor que faça o mesmo (o "python -m http.server"
  não faz: nele, abra os arquivos com .html).
